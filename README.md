# dsh-mail

通过邮件运行 DSH 任务。插件使用 IMAP 或 POP3 收信，按规则创建 DSH 会话，任务结束后通过 SMTP 回复状态和 Agent 的最后输出。

支持多个邮箱、发件人验证、邮件指定工作目录和文本附件。邮件任务默认使用完整权限，无需审批；同一工作目录的任务依次执行。

## 安装

需要 Bun ≥ 1.4.4、DSH 0.2.x（最低 `0.2.2-alpha.2`），以及已开启 IMAP 或 POP3 收信及 SMTP 发信的邮箱。Node.js 最低为 24.9.0，需处于官方维护期并满足所用 DSH 的要求；Node 22 和 DSH 0.2.1 及更早版本不受支持。项目的依赖管理、构建和测试使用 Bun。请先安装相应 DSH 并配置好模型，再从源码安装：

```sh
git clone https://github.com/iMMIQ/dsh-mail.git
cd dsh-mail
bun install --frozen-lockfile
bun run build
dsh plugin --profile web add "$PWD"
dsh --profile web --no-open
```

打开 DSH，进入 **插件 → 已安装 → dsh-mail → 包含的组件 → 配置**：

1. 填写邮箱地址、邮件服务器、登录密码或授权码，以及允许发指令的邮箱。
2. 点击“保存并启用”，连接检查成功后自动开始收信；失败时保持暂停。
3. 按页面示例发送任务邮件，结果默认回信到允许的发件邮箱。

默认收发信共用服务器和密码，Agent 模式与模型沿用 DSH 当前设置。POP3 收信、分开的 SMTP 服务器、登录名、端口、内部 CA 证书和任务参数都在折叠选项中。

授权码由 DSH 凭据存储管理，保存后只显示“已设置”；留空保留原值。连接检查只验证登录，不发送邮件。插件首次安装处于暂停状态，DSH 必须保持运行才能处理邮件。手动配置和来源验证见[配置说明](docs/configuration.md)。

## 使用

从配置允许的地址发送邮件，主题以 `[DSH]` 开头，正文如下：

```text
---
workspace: /srv/projects/my-project
---
检查最近十次提交，修复发现的问题并运行相关测试。
```

`workspace` 必须是 DSH 所在机器上已存在的绝对目录，不需要目录白名单，不展开 `~` 或环境变量。正文开头的配置段只接受 `workspace`。来源验证和权限配置见[配置说明](docs/configuration.md)。

新任务邮件创建会话；直接在通知邮件的历史引用上方回复，就会继续同一个 DSH 会话，无需重复填写 `workspace`。执行中收到的回复按接收顺序排队。完成、失败、取消、超时或需要核对时，插件自动回复本轮状态、会话编号、实际目录、摘要和最后文字输出。结果邮件提供 HTML 和纯文本版本。HTML 模板突出状态、摘要与 Agent 最后回复，渲染 Markdown 列表、表格、代码块和链接，并显示已记录的耗时、模型、步数、工作目录及会话编号，无需额外配置。邮件不包含思考内容或工具日志，超长输出会缩短，完整内容保留在 DSH 会话中。

开启设置页的“其他 DSH 会话也发送邮件通知”，该 DSH 实例内从界面、CLI 或定时任务创建的主会话也会在每轮结束后发信，默认复用第一条规则的回信配置。回复通知即可继续原会话，保留其目录、模式和权限。各独立 DSH 实例需分别加载插件。

默认验证 DKIM；“信任的内部邮箱”可对指定完整地址跳过签名验证，允许发件人列表仍然生效。收件确认默认开启，验证通过并入队后先发确认，再发执行结果。

支持 IMAP、POP3 收信与 SMTP 发信，均可使用直接 TLS 或 STARTTLS（POP3 使用 STLS）。POP3 默认每 60 秒检查新邮件，首次启用跳过已有邮件，保留服务器邮件并按 UIDL 去重。支持 UTF-8 文本附件。无法关联会话的回复会暂存；二进制附件和结果文件附件不受支持。真实邮箱服务商联调尚未完成。

## 管理与开发

任务取消、重试和收发信排查见[故障处理](docs/operations.md)。已有安装升级到 0.2 时，请先阅读[升级说明](docs/upgrading.md)。

```sh
bun run check
```

执行构建、类型检查和测试，无需真实邮箱或模型密钥。修改源码后重新构建并重启 DSH。

POP3 使用 `node-pop3` 的 ESM 入口。`patches/` 中的 Bun 补丁提供 STLS、原始字节流修正、响应大小限制和连接关闭接口，由 `bun install` 自动应用；升级依赖时需保留这些能力并运行 POP3 测试。

CI 保留最低支持版与最新版两个任务，使用各版本配套的 Cordis 依赖，在任务内检查符合要求的 Node 24、26。可用 `bun run test:compat 0.2.2-alpha.2` 验证指定 DSH；后面可追加多个 Node 可执行文件路径。
